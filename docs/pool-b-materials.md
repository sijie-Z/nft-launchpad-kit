# Pool B — 真实项目验证物料（池 B）

> Phase 1B 验证池 B：**真实项目方是否愿意用平台完成发行**。
> 目标：3-5 个团队中 ≥2 个完成真实发行，且 ≥1 个有再发意愿（或付费/带量表态）。
> 注意：本池验证的是**发行流程（workflow value）**，不是主网商业价值 —— 话术必须诚实。

---

## 1. 招募渠道

| 优先级 | 渠道 | 说明 |
|--------|------|------|
| 1 | 作者认识的项目/社区（游戏公会、Discord 社区、音乐人） | 信任最高 |
| 2 | AI/内容创作社区（有粉丝基础的个人或小团队） | "会员卡/凭证"场景最贴合 |
| 3 | 本地/中文 Web3 社区 | 补充 |

**配比**：3-5 个团队，至少 1 个来自完全陌生的渠道。

---

## 2. 第一句话话术（直接给价值，不问意见）

> 我做了个开源平台，可以让 AI 自动发行 NFT/会员卡/凭证（测试网阶段，不花真钱）。我想找几个真实项目验证发行流程是否够简单 —— **我免费帮你完整发行一次**：你只需要告诉我需求（发什么、给谁、多少量、什么时候），剩下我来。愿意试试吗？

**如果对方问"测试网有什么用"（诚实回答）**：

> 现在是测试网验证阶段，重点是验证**发行流程本身**是否顺 —— 就像餐馆先试菜再开张。等流程验证有效，下一阶段会带往主网（主网上线前会做专业安全审计）。这次的意义是：我们俩一起把"从 0 到发行"跑通，你零成本拿到一次完整发行经验。

## 5. 结果判定（池 B 停止条件）

| 结果 | 判定 |
|------|------|
| ≥2 个团队完成真实发行 | ✅ 流程验证通过 |
| 且 ≥1 个明确安排下一次发行（L3） | ✅ 产品价值信号 |
| 且 ≥1 个有付费/带量表态（L4-L5） | ✅ 商业信号（详见承诺梯度） |

**承诺梯度**（对每个完成发行的团队追问）：

```
L0 挺有意思 → L1 愿意试 → L2 完成发行 → L3 愿意再发
→ L4 愿意带真实用户来 → L5 愿意为下次发行付钱
```

**L5 的追问方式**（不要问"你愿意付吗"）：

> "如果下次发行我们按 ¥XXX 收费（托管+支持），你还会继续吗？"
> "那下次你准备什么时候发？"
> "可以现在先预订/支付吗？"

## 6. 案例授权（作品价值）

每个完成的团队询问：

> "可以把你们作为案例放在项目 README 上吗（'Used by X to issue Y'）？"

目标：≥2 个同意（匿名或具名皆可）。
